## TensorRT / ONNX optimization cluster

Packages: `tensorrt`, `tensorrt-cu12`, `tensorrt-cu13`, `tensorrt-llm`, `tensorrt-rtx`, `torch-tensorrt`, `onnx-graphsurgeon`, `polygraphy`, `onnxslim`.

Use this cluster when a user is converting ONNX, building TensorRT engines, debugging provider/runtime failures, comparing outputs, or trying to accelerate inference beyond PyTorch/ONNX Runtime.

## v1.6 — LLM serving and OpenAI-compatible local server clusters

- LLM serving engines: `vllm`, `sglang`, `text-generation` client.
- Gateway/router: `litellm`, existing `openai` package.
- Distributed serving: `ray` plus existing Kubernetes/Triton deployment packages.
- Attention/kernels: `flash-attn`, `flashinfer-python`, `flashinfer-cubin`, `flashinfer-jit-cache`, `sgl-kernel`.
- Quantization/compression: `compressed-tensors`, `llmcompressor`, `gptqmodel`, `autoawq`, `auto-gptq`, `torchao`, existing `bitsandbytes`.
- Structured output: `xgrammar`, `outlines`, `lm-format-enforcer`, `guidance`.
- API streaming support: `msgspec`, `uvloop`, `httptools`, `h11`, `sse-starlette`, `watchfiles`.
