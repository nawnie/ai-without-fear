# Dataset Design and Quality Laws

## Purpose

This card is the core AIWF dataset doctrine. Most failed LoRAs and fine-tunes are not mysterious. They are predictable data failures.

## Law 1 — The model learns the pattern you actually give it

A dataset is not your intention. It is the evidence.

If every good answer is long, the model learns long. If every image of a person is from one angle, the model learns that angle. If every support answer includes hedging, the model learns hedging. If captions mention irrelevant background objects, the image model learns those objects as part of the concept.

## Law 2 — Repetition is a volume knob and a weapon

Repeating an example increases its influence. This can help rare concepts, but it can also cause memorization, artifacts, trigger overbinding, and mode collapse.

## Law 3 — Captions are control surfaces

For diffusion training, captions decide what the model can separate:

- what is the subject
- what is style
- what is background
- what should change
- what should remain stable

Bad captions glue everything together.

## Law 4 — Negative space matters

The model needs variation to learn what does **not** define the concept.

For image identity LoRA:

- different backgrounds
- different lighting
- different expressions
- different clothing
- different distances
- different angles

For chatbot SFT:

- different phrasing
- edge cases
- refusals/uncertainty
- short and long answers
- different user competence levels

## Law 5 — Holdout data is non-negotiable

If every example is trained on, you cannot tell whether the model generalized or memorized.

Minimum split:

- train
- validation/check prompts
- adversarial/failure set

## Law 6 — Label consistency beats label volume

A small clean dataset can outperform a large confused dataset. Contradictory examples teach unstable behavior.

## Law 7 — Dataset provenance is part of the model

For AIWF, every dataset needs:

- source
- rights/license
- consent status
- date collected
- preprocessing steps
- filtering rules
- excluded material
- known gaps
- intended use
- out-of-scope use

## Law 8 — Synthetic data must be quarantined and labeled

Synthetic data can help, but it can also collapse diversity, launder errors, and make evals meaningless.

Track:

- generated by what model
- prompt used
- human edits
- acceptance criteria
- whether it is used for training, eval, or augmentation

Never train and evaluate on synthetic data from the same generator without explicit contamination checks.

## Law 9 — Deduplication is not optional

Duplicates inflate metrics and cause memorization. Near-duplicates matter too.

For images:

- perceptual hash
- resolution/aspect buckets
- face/subject similarity checks where appropriate

For text:

- exact hash
- normalized text hash
- embedding similarity
- source overlap

## Law 10 — Evaluation data must not leak into training

This is especially important for small personal datasets. If the eval set leaks, you are measuring memory.

## Dataset types

### LLM SFT dataset

Needs:

- instruction/user input
- assistant response
- optional system prompt
- optional conversation history
- task label
- source/provenance
- quality rating

Common formats:

- Alpaca-style instruction/input/output
- ShareGPT/chatml-style conversations
- tool-call schemas

### Preference dataset

Needs:

- prompt
- chosen response
- rejected response
- criterion
- judge/source
- notes for ambiguous cases

### Embedding/reranker dataset

Needs:

- query
- positive passage(s)
- hard negative passage(s)
- source document IDs
- relevance labels

### Image LoRA dataset

Needs:

- image
- caption/tags
- concept trigger
- rights/consent metadata
- quality flags
- crop/resize metadata

### Video LoRA dataset

Needs:

- clip
- frame count/fps/resolution
- caption
- motion label
- camera movement label
- subject identity/style metadata if relevant
- rights/consent metadata

### Voice dataset

Needs:

- audio clip
- transcript
- speaker consent
- noise/quality flags
- language/accent notes
- use restrictions

## AIWF quality gates

Before training:

- no unlicensed or unknown-rights data in distribution-targeted models.
- no identity/voice/person data without explicit consent.
- no eval leakage.
- captions reviewed.
- duplicates removed or intentionally weighted.
- dataset card written.

After training:

- compare base vs trained output.
- run held-out prompts.
- run failure prompts.
- inspect memorization risk.
- document model card.
