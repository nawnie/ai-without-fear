# Training Telemetry, Experiment Tracking, and Run Evidence

## Scope
This card covers what to log during a training run so the result can be debugged, compared, reproduced, and explained later. It applies to LLM LoRA/QLoRA, image LoRA, video LoRA, voice fine-tuning, embedding/reranker training, and VLM tuning.

## Core rule
> If you cannot explain why a checkpoint exists, you do not have an experiment. You have a file.

## What must be captured

### Environment
- OS,
- GPU model and VRAM,
- driver version,
- Python version,
- torch version,
- CUDA build/runtime,
- trainer repo and commit,
- package lock or pip freeze,
- launch command.

### Dataset
- dataset manifest path,
- row/file counts,
- split counts,
- dedup score,
- privacy/provenance status,
- caption/schema validation status,
- train/eval leakage status.

### Model/training config
- base model,
- adapter type,
- rank/alpha/dropout,
- target modules,
- optimizer,
- learning rate,
- batch size,
- gradient accumulation,
- precision,
- gradient checkpointing,
- max steps/epochs,
- scheduler,
- seed,
- resolution/frame settings for diffusion/video.

### Runtime telemetry
- loss curve,
- validation loss if available,
- learning rate curve,
- GPU utilization,
- VRAM used,
- temperature,
- step time,
- checkpoint sizes,
- OOM events,
- warnings/errors.

### Output evidence
- sample generations or responses,
- fixed prompt deck results,
- evaluation metrics,
- qualitative notes,
- failure examples,
- final model card.

## Tracking tools

### TensorBoard
Good default local visualization tool. Useful for metrics like loss/accuracy, graphs, histograms, images, and embeddings. PyTorch supports TensorBoard via tutorials and utilities.

### Weights & Biases
Strong for hosted experiment tracking, system metrics, configs, artifacts, sweeps, and collaboration. Useful when the user is comfortable with an online service.

### MLflow
Strong open-source lifecycle platform for experiment tracking, model registry, evaluation, and production-oriented workflows.

### Plain markdown + CSV
Best beginner fallback and AIWF default. Not fancy, but portable and RAG-friendly.

## AIWF run evidence folder
```text
run_YYYY-MM-DD_name/
  config/
    trainer_config.yaml
    dataset_manifest.json
    environment_report.json
  logs/
    train.log
    metrics.csv
    warnings.md
  eval/
    prompt_deck.md
    samples/
    eval_results.json
  checkpoints/
    adapter_final.safetensors
  README_RUN_CARD.md
  MODEL_CARD_DRAFT.md
```

Note: use day-only folder naming where possible for project changelogs; exact logs can contain runtime values if generated by trainer.

## Beginner diagnostic signs
- Training loss drops but validation quality worsens: overfit or leakage.
- Loss flatlines immediately: LR too low, no trainable params, broken targets, bad masking.
- Loss NaN: precision/optimizer/data issue.
- Samples all look like dataset: too many repeats/epochs, too narrow data.
- Samples ignore LoRA: too low strength, wrong trigger, underfit, wrong target modules.
- Great eval but poor real prompts: eval leakage or narrow prompt deck.

- dataset doctor report,
- source log,
- validation deck,
- before/after samples,
